This [tutorial](https://flusp.ime.usp.br/git/sending-patches-with-git-and-a-usp-email/) explains an important principle of many Git and Linux kernel communities: contributions are often sent as patches by email instead of Pull Requests or Merge Requests.

The goal is to learn how to use `git send-email` with a USP email account, which requires extra OAuth configuration. The tutorial also uses `kworkflow (kw)` to simplify setup and patch submission.

## Takeaways

* Some open source communities use email-based workflows

  Instead of web platforms, contributions are reviewed through mailing lists. This is common in the Linux kernel ecosystem.

* `git send-email` is the standard tool for patch submission

  It converts commits into patch emails and sends them in the expected format, preserving metadata and commit history.

* USP/Gmail accounts require OAuth authentication

  Since basic password authentication is no longer supported, sending patches requires an OAuth-compatible setup.

* Two setup approaches were presented

  **Option A: Git credential helper**

  * use `git-credential-gmail`
  * generate OAuth tokens
  * configure Git locally
  * send patches normally

  **Option B: Email proxy**

  * run a local SMTP proxy
  * authenticate through browser OAuth flow
  * connect `git send-email` to the proxy

* `kw send-patch` simplifies configuration

  Instead of manually editing Git settings, `kw` helps configure sender name, email, SMTP server, and ports.

* Always simulate before sending

  Using:

  ```bash
  kw send-patch --send --simulate
  ```

  allows checking recipients, subject, CC list, and patch contents before actual submission.

* Patch emails are commit-based

  A normal Git commit can be transformed into a formatted contribution email, making clean commit history very important.

* Email workflows emphasize review discipline

  Correct recipients, clear commit messages, and proper patch structure matter more than in many web-based workflows.

## Challenges I Faced

I used the **email proxy** approach and the Dockerfile required minor adjustments to run on Fedora. After that, the process worked smoothly.

## Commands Cheatsheet

```bash
### OAUTH HELPER
git credential-gmail --set-client
git credential-gmail --authenticate --external-auth

### KW SETUP
kw send-patch --setup --name "Your Name"
kw send-patch --setup --email "you@usp.br"
kw send-patch --setup --smtpserver "127.0.0.1"
kw send-patch --setup --smtpserverport "2587"

### SEND PATCHES
kw send-patch --send -1 --private --simulate --to='email@example.com'
kw send-patch --send -1 --private --to='email@example.com'

### EMAIL PROXY
docker compose up --build
docker exec -it <container> /bin/bash
emailproxy --no-gui --external-auth --config-file /app/emailproxy.config
```
