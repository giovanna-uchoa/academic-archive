This [tutorial](https://flusp.ime.usp.br/kernel/modules-intro/) is the third part of the newcomers series. The goal is learning how to make a simple Linux kernel module and how to create build configurations for new kernel features.

## Takeaways

* What kernel modules are
  
   Kernel modules are pieces of code that can be dynamically loaded and unloaded from the kernel. This allows extending functionality (e.g. device drivers) without recompiling or rebooting the system. Without modules, everything must be compiled directly into the kernel image. Modules make the system more flexible and reduce the need for full rebuilds.

* Modules are a good entry point to kernel development

  They provide an isolated way to experiment with kernel code without modifying core parts of the system.

* Kconfig defines configuration symbols

  Using `config`, we define symbols that become entries in `.config` and show up in tools like `menuconfig`.

  Key attributes:

  * `tristate`: can be `y` (built-in), `m` (module), or `n` (disabled)
  * `bool`: only enabled/disabled.
  * `depends on`: controls visibility and availability
  * `select`: automatically enables other symbols
  * `help`: text to be displayed as auxiliary info

* kbuild integrates modules via Makefiles

  After adding a module to Kconfig,  it requires linking it in the Makefile:

  ```bash
  obj-$(CONFIG_SIMPLE_MOD) += simple_mod.o
  ```

* Configuration is done via tools, not manual edits
  Using:

  ```bash
  kw build --menu
  ```

  allows enabling the module (`m`) safely.

* Module management commands

  * `modprobe`: loads/unloads modules and handles dependencies
  * `insmod`: loads modules without dependency resolution
  * `modinfo`: shows metadata about a module
  * `dmesg | tail `: kernel logs essential for feedback and verify module behaviour 

* Build cycle is iterative

  Typical flow:

  * clean (`kw build --clean`)
  * rebuild (`kw build`)
  * deploy module (send `.ko` to VM)
  * test in VM

  In the VM:

  * copy `.ko` to `/lib/modules/...`
  * running `depmod` to update dependencies
  * then use `modprobe` to load/unload
  * check logs with `dmesg | tail`

## Commands Cheatsheet

```
### MAKE COMMANDS TO CONFIGURE, COMPILE, AND INSTALL MODULES
make -C "$IIO_TREE" menuconfig # manage `.config` w/ a TUI
make -C "$IIO_TREE" -j$(nproc) Image.gz modules # compile kernel image and modules
make -C "$IIO_TREE" modules_install # install modules
make -C "$IIO_TREE" modules_prepare # refresh modules for compilation
make -C "$IIO_TREE" M=<path-of-dir-to-build> # compile only a subset of the tree

### MANIPULATING MODULES
modinfo <module_name> # see information about module of given name
insmod <module_file.ko> # loads module at given location
rmmod <module_name> # unloads module of given name
modprobe <module_name> # loads module of given name and its dependencies 
modprobe -r <module_name> # unloads module of given name
depmod --quick # updates the module dependency list only if a module is added or removed

### SEE KERNEL LOGS
dmesg | tail # see last logs
```
