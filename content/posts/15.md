For the second phase of the course, after exploring several suggested FLOSS projects, I chose to contribute to **ArKanjo** — a CLI tool for detecting function-level code duplication. Two things pulled me toward it: the project is well-documented, which lowers the barrier for a first-time contributor, and it felt like a fitting payback — ArKanjo itself was the tool used to extract my first-phase contribution from another codebase.

### Getting started: a broken baseline

Before touching any code, I wanted to make sure my changes would be safe, which meant understanding the test structure and getting a passing baseline first. I tried running the e2e test suite, and it kept failing.

I spent a while trying to fix it myself, but the failure wasn't a simple one-line patch — it touched enough "business" rules (updating the test structure, regenerating the expected output files, and more) that fixing it blind felt like the wrong call for someone still ramping up on the codebase. Rather than force a fix I wasn't confident in, I opened an issue describing what I'd found: [#39](https://github.com/arkanjo-tool/arkanjo/issues/39).

The maintainer responded quickly, confirming it wasn't environment-specific and had a real fix in the works:

> Thanks for the report!
>
> This wasn't a macOS-specific issue. The **E2E tests** had some inconsistencies, and I've since updated the expected test data, improved the test implementation, and added the E2E tests to the CI pipeline so issues like this are caught automatically.

That exchange was a good early signal: the maintainer was responsive, and the fix went beyond a patch — CI was updated so the same class of issue would be caught automatically going forward.

### First contribution: a proactive fix

With the baseline sorted, I moved on to my actual task, which required understanding the output of `arkanjo explorer` combined with the `--template` flag. While setting things up to test it manually, `explorer` failed at startup with file-not-found errors. Digging in, I traced it to `DiffMethod` saving absolute file paths into `output_parsed.txt` instead of relative ones — because `fs::path::operator/` silently discards the left-hand prefix when the right-hand operand is absolute, path lookups in query commands resolved to the wrong directory. `ASTMethod` wasn't affected, since it built paths differently and was already relative.

I fixed it by relativizing both path components in `DiffMethod::execute()` right after similarity computation, before results were saved — keeping the fix scoped to that function without touching the parts of the code that still legitimately needed absolute paths for file I/O. I opened [#37](https://github.com/arkanjo-tool/arkanjo/pull/37), which was accepted on the first revision.

### Second contribution: a known enhancement

Next I picked up an open enhancement request tracked by the maintainers: [#38](https://github.com/arkanjo-tool/arkanjo/pull/38). This one took three revisions to land, and the back-and-forth was less about correctness and more about fit: what belongs in the help output without adding verbosity or duplicating information already shown elsewhere, and how to adjust the output format so it stayed readable as the amount of information grew. It was a useful contrast to [#37](https://github.com/arkanjo-tool/arkanjo/pull/37) — less about spotting a bug, more about converging on the project's own conventions through review.

### Takeaway

Looking back, the onboarding detour wasn't wasted time even though it didn't produce a merged fix on its own: it surfaced a real bug in the test suite ([#39](https://github.com/arkanjo-tool/arkanjo/pull/39)), and the process of digging through the codebase to understand it gave me the context to catch and fix a second, unrelated bug ([#37](https://github.com/arkanjo-tool/arkanjo/pull/37)) while doing the task I'd actually signed up for. The enhancement request ([#38](https://github.com/arkanjo-tool/arkanjo/pull/38)  then pushed me to think less about "does this work" and more about "does this fit the project" — a different kind of contribution, and one I found just as valuable.
