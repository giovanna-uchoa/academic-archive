This [tutorial](https://flusp.ime.usp.br/kernel/char-drivers-intro/) is the last part of the newcomers series. The goal is to introduce Linux character devices through the implementation of a basic character device driver.

Character drivers define how devices behave, controlling data flow and access between user applications and kernel-managed hardware or virtual devices.

## Takeaways

* Character devices handle small sequential data transfers

  They are commonly accessed byte-by-byte or in small chunks through standard file operations such as `read()` and `write()`.

  Examples:

  * `/dev/ttyS0`
  * `/dev/input/mouse0`
  * `/dev/kmsg`
  * `/dev/zero`

* Devices are represented as files in Linux

  Many hardware and virtual devices appear under `/dev`, allowing interaction through normal file system syscalls.

* Major and minor numbers identify devices

  Each device file maps to a device ID:

  * **Major number** → selects the driver
  * **Minor number** → distinguishes device instances or modes

* Device numbers can be dynamically allocated

  Kernel helpers like:

  ```c
  alloc_chrdev_region()
  ```

  reserve a major number and minor range for drivers.

* Useful macros manage device IDs

  Common helpers:

  * `MAJOR(dev)`
  * `MINOR(dev)`
  * `MKDEV(major, minor)`

* Drivers expose behavior through `file_operations`

  Character drivers register functions for common syscalls such as:

  * `open`
  * `release` (close)
  * `read`
  * `write`

* Kernel code must safely access user memory

  Direct access to user pointers is unsafe. Drivers use:

  * `copy_from_user()`
  * `copy_to_user()`

  to transfer data between user space and kernel space.

* `struct cdev` connects identity and behavior

  The kernel links device numbers with supported operations using the `cdev` structure.

## Commands Cheatsheet

```bash id="6hzt8v"
### INSPECT DEVICES
cat /proc/devices
ls -l /dev/

### CHECK DEVICE NUMBERS
stat /dev/ttyS0

### CREATE DEVICE NODE
sudo mknod /dev/mychardev c <major> <minor>

### LOAD / UNLOAD DRIVER
sudo insmod mydriver.ko
sudo rmmod mydriver
lsmod | grep mydriver

### TEST DEVICE
echo "hello" > /dev/mychardev
cat /dev/mychardev

### LOGS
dmesg | tail
```
