These tutorials ([6](https://flusp.ime.usp.br/iio/iio-dummy-anatomy/), [7](https://flusp.ime.usp.br/iio/experiment-one-iio-dummy/)) studies the Linux Industrial I/O (IIO) subsystem through the `iio_simple_dummy` driver, using it as an entry point to understand how sensor drivers are organized in the kernel.

## Main Takeaways

* `iio_dummy` is one of the best starting points for learning IIO

  It is a simplified teaching driver with extensive comments that explain subsystem internals and common driver patterns.

* Channels are the core abstraction in IIO

  A single device may expose multiple channels representing different measurements or axes, such as:

  * accelerometer: X, Y, Z
  * light sensor: visible + infrared
  * thermometer: temperature only

* `struct iio_chan_spec` defines device capabilities

  This structure describes how each channel behaves, including:

  * measurement type (`IIO_VOLTAGE`, `IIO_ACCEL`, `IIO_MAGN`)
  * indexing and modifiers
  * readable/writable attributes
  * shared scale or frequency values
  * buffered capture layout

* Sysfs attributes are generated from channel definitions

  Fields declared in `iio_chan_spec` become files such as:

  * `in_voltage0_raw`
  * `in_accel_x_raw`
  * `in_magn_scale`

* `read_raw()` and `write_raw()` connect userspace to driver state

  These callbacks interpret requested attributes and map them to internal values stored in the driver.

* Buffers require explicit scan configuration

  `scan_index` and `scan_type` define ordering, storage size, resolution, and data format for buffered samples.

* Probe functions assemble the device

  A typical IIO probe routine:

  * allocates `iio_dev`
  * initializes private state
  * registers channels
  * configures events/buffers
  * registers the device

* Extending a driver is systematic

  Adding a fictional 3-axis compass required:

  * new `IIO_MAGN` channels
  * raw X/Y/Z values
  * shared scale
  * buffer indexes
  * updates to `read_raw()`

* Sysfs is useful for validation

  New channels can be verified immediately through `/sys/bus/iio/devices/`.

* The same concepts scale to real hardware drivers

  Although `iio_dummy` is virtual, the same architecture is used by real sensors connected through I2C, SPI, and other buses.

## Commands Cheatsheet

```bash id="e9s1wa"
### BUILD ONLY THE IIO DUMMY DRIVER
make M=drivers/iio/dummy

### INSTALL MODULES
sudo make modules_install

### LOAD / UNLOAD MODULE
sudo modprobe iio_dummy
sudo modprobe -r iio_dummy

### CHECK MODULE
modinfo iio_dummy
lsmod | grep iio_dummy

### INSPECT IIO DEVICES
ls -l /sys/bus/iio/devices/
ls -l /sys/bus/iio/devices/iio:device0/

### READ SENSOR ATTRIBUTES
cat /sys/bus/iio/devices/iio:device0/name
cat /sys/bus/iio/devices/iio:device0/in_voltage0_raw
cat /sys/bus/iio/devices/iio:device0/in_accel_x_raw

### CONFIGFS SETUP
sudo mkdir /mnt/iio_experiments
sudo mount -t configfs none /mnt/iio_experiments

### CREATE DUMMY DEVICE
sudo mkdir /mnt/iio_experiments/iio/devices/dummy/my_device

### REMOVE DEVICE (IF MODULE IS BUSY)
sudo rmdir /mnt/iio_experiments/iio/devices/dummy/my_device

### AFTER ADDING COMPASS CHANNELS
cat /sys/bus/iio/devices/iio:device0/in_magn_x_raw
cat /sys/bus/iio/devices/iio:device0/in_magn_y_raw
cat /sys/bus/iio/devices/iio:device0/in_magn_z_raw
cat /sys/bus/iio/devices/iio:device0/in_magn_scale
```
